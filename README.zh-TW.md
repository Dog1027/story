# Story

[English](README.md) | 繁體中文

AI 文字冒險遊戲，可以在終端機或瀏覽器裡玩，也可以和朋友一起連線玩。劇情由 Gemini 即時生成，你的每個選擇都會影響故事的走向。

設計原則是 **AI 負責說故事，程式負責記憶與把關**：AI 每回合只「提議」劇情與狀態變化，由程式驗證後才寫進遊戲狀態。所以 AI 沒辦法一句話讓你死掉，也不會忘記你背包裡有什麼；反過來，魯莽的選擇會帶來真正的傷勢，傷勢累積到致命就會死。

## 特色

- **完整的故事結構**：開場前先規劃隱藏的四幕大綱，連同一個玩家不知道的真相：前兩幕埋伏筆，第三幕揭露。程式追蹤進度、控制節奏，約 30 回合走到結局，不會太早結束，最後附上尾聲與結局名稱
- **身體與精神狀況**：沒有生命值，改用「右臂撕裂傷（重）」「恐懼（中）」這類狀態。身體傷勢累積到致命才會死亡，精神狀態只影響表現
- **隱藏的遊戲內時間**：傷勢會隨時間痊癒，重傷則要在劇情中接受治療
- **限時模式**：情勢緊迫時，要在倒數內做出決定
- **長期記憶**：每回合的劇情都保留原文，AI 看得到整段故事；故事長到超過上限時，最舊的部分才自動壓縮成摘要
- **題材包**：武俠、克蘇魯、靈異、怪物與異形、賽博龐克，各有自己的寫作指引、開頭靈感與轉折靈感。開局時依故事前提自動挑選，也可以自己指定；想自己寫題材包不用改程式，見 [docs/genres.md](docs/genres.md)
- **隨機開頭**：開新故事時從題材包的開頭靈感裡抽一個，按「換一個」重抽，或按「幫我想」讓 AI 想一個全新的
- **多人模式**：1 到 4 位玩家各自扮演一位角色，每個人有自己的狀態、背包與選項，大家都行動後才推進一回合。每個人用自己的手機或電腦連進網頁一起玩

## 開始玩

需要：

- [uv](https://docs.astral.sh/uv/)：會自動安裝 Python 3.14 與相依套件
- Gemini API key：到 [Google AI Studio](https://aistudio.google.com/apikey) 免費申請
- [just](https://github.com/casey/just)（建議）：常用指令的捷徑。沒裝的話，每個指令都可以改用下面表格裡的 `uv run …`

```bash
just play
```

第一次執行時，遊戲會請你貼上 API key，並詢問要不要儲存（存在 `~/.config/story/api_key`）。也可以改用環境變數 `GEMINI_API_KEY`。

**語言**：預設是繁體中文。想玩英文版，在指令前面加上 `STORY_LANG=en`，例如 `STORY_LANG=en just play`、`STORY_LANG=en just serve`。故事、介面、題材包都會換成英文；同一台伺服器上的所有人用同一種語言。

## 玩法一覽

| 指令 | 不用 just 的寫法 | 說明 |
|---|---|---|
| `just play` | `uv run story` | 終端機版 |
| `just plain` | `uv run story --plain` | 純文字版（只用 input/print） |
| `just serve-solo` | `uv run story-web --host 0.0.0.0` | 網頁版，每個人各自玩 |
| `just serve` | `uv run story-web --party --host 0.0.0.0` | 網頁版，線上多人一起玩同一局 |
| `just start`／`just stop` | | 在背景啟動／關閉線上多人的伺服器（已經在執行就重啟，輸出寫在 `server.log`） |

網頁伺服器預設用 8080 埠（`just serve 9000` 可以換）。在瀏覽器打開 `http://這台電腦的IP:8080`，本機就是 <http://localhost:8080>。手機和電腦用同一個頁面，會跟著系統切換淺色、深色。

### 網頁版：每個人各自玩

- 進入時先輸入名字，每個名字有自己的存檔，同一個名字同時只能有一個人在線
- 每個玩家輸入自己的 Gemini API key，key 只留在這次連線裡，不會存到伺服器
- 同時在線最多 10 人

### 網頁版：線上多人

伺服器用自己的 API key 呼叫 AI（先執行一次 `just play` 存好 key，或設定 `GEMINI_API_KEY`），玩家不用輸入。

- 進入時輸入名字，名字就是你的角色。第一個進來的人是房主，由房主選「開始遊戲」（一個人也能開始，最多 4 人）
- 房主負責選故事前提、要不要接續存檔、重新開始；房主送出前提後，大家會先看到前提，等 AI 寫好開場就一起進入故事
- 遊戲中每個人看到自己的選項，誰先行動都可以，有人行動時其他人會收到通知，大家都行動後才推進。限時模式的倒數由伺服器統一計時，等大家都看完劇情才開始
- 中途斷線可以用同一個名字回來；其他人都行動了而斷線的人還沒回來時，那個角色這回合算「暫時離開」
- 房主離線時，交給下一位在線的玩家當房主
- 故事結束後回到大廳，可以再玩一局。整台伺服器只有一個房間，大家都進同一局

> ⚠ 網頁伺服器會開放同一個網路裡的其他電腦連線。目前沒有 HTTPS，玩家輸入的 API key 會以明文傳送；名字也沒有密碼保護，知道名字的人可以接著玩那個存檔。只建議在信任的網路裡使用。

## 操作

**終端機版**

| 按鍵 | 功能 |
|---|---|
| ↑↓、數字、滑鼠 | 選擇選項 |
| 直接打字 | 自由行動，不照選項走 |
| Enter（文字顯示中） | 加速，再按一次全部顯示 |
| 滑鼠滾輪 | 捲動故事。文字還在顯示時也能往上捲回去看，捲回最底就繼續跟著新文字 |
| F2 | 選擇配色主題（上下移動就能預覽，會記住） |
| `/` 或 Ctrl+P | 開啟指令選單 |
| Ctrl+T | 看程式記住了什麼 |
| Ctrl+R | 重新開始 |
| F1 | 說明 |
| Ctrl+Q | 存檔並離開 |

**網頁版**：點選項，或直接在下方輸入框寫下行動（電腦上也可以在輸入框用 ↑↓ 選擇後按 Enter）。文字顯示中點一下故事區或按 Enter 會加速，再按一次全部顯示。右上角的 ⋯ 選單有「程式記住的東西」、「重新開始」、說明與外觀（淺色／深色）。

**存檔**：每回合都會自動存檔，下次進來可以接續。

| 玩法 | 存檔 |
|---|---|
| 終端機版 | 目前資料夾的 `save.json` |
| 網頁版各自玩 | `saves/名字.json` |
| 網頁版線上多人 | `saves/party.json`（同一組玩家才會接續） |

## 程式架構

```
src/story/
├── core/       核心：遊戲規則、呼叫 AI、存檔
├── prompts/    給 AI 的提示詞（markdown），改了不用動程式
├── genres/     題材包
└── shells/     外殼
    ├── client.py   給真人玩的介面共用的流程
    ├── textual/    終端機版的畫面
    ├── web/        網頁版的伺服器與畫面
    ├── room.py     線上多人的房間
    └── plain.py    純文字版
```

分成三層，各自只做一件事：

- **核心**（`core/`）：像呼叫 LLM 一樣，送一句文字進去、拿回覆出來（劇情、選項、狀態……）。不知道畫面的存在，所以要做 Discord 機器人之類的新外殼，也只需要處理顯示和輸入。純文字版就是最簡單的例子
- **共用層**（`shells/client.py`）：什麼時候顯示什麼。開局要問什麼、劇情打完字才出現選項、結局一段一段出現、線上多人怎麼連房間。終端機版和網頁版都用這一份
- **介面**（`textual/`、`web/`）：只決定長什麼樣子

判斷新功能放哪裡：改變遊戲結果或事實 → 核心；改變真人看到的順序、時機、流程 → 共用層；改變長相 → 介面。

每個檔案的詳細說明見 [docs/files.md](docs/files.md)，待辦與改進方向見 [docs/roadmap.md](docs/roadmap.md)。

## 調整

常用的設定都是程式檔開頭的常數，或獨立的文字檔：

- **故事長度、使用的模型、傷勢與痊癒規則**：`src/story/core/engine.py`
- **AI 的寫法**（寫作規則、劇情字數、節奏提醒、尾聲……）：`src/story/prompts/` 的 markdown 檔。先看 [src/story/prompts/README.md](src/story/prompts/README.md)，裡面有「想改什麼 → 改哪裡」的對照
- **題材包**：`src/story/genres/`，寫法見 [docs/genres.md](docs/genres.md)
- **終端機版的配色主題、打字速度**：`src/story/shells/textual/style.py`。狀態的顏色會從主題的成功／警告／錯誤色算出來
- **網頁版的配色、字型、打字速度**：`src/story/shells/web/static/style.css` 開頭的顏色設定，與 `app.js` 開頭的常數

**新增語言**：在 `src/story/prompts/` 與 `src/story/ui/` 各加一個資料夾，放一整套同名的檔案（複製 `en/` 再翻譯），用 `STORY_LANG` 選擇。測試會檢查每種語言的檔案、段落與變數都一樣。

## 測試與評估

| 指令 | 做什麼 |
|---|---|
| `just test` | 全部測試（約 30 秒）。不會連到 Gemini，也不會動到你的存檔或 API key。改完功能後跑一次，確認原本的功能沒有被弄壞 |
| `just prompts` | 預覽送給 AI 的完整提示詞，不會呼叫 AI。例如 `just prompts turn`、`just prompts --party` |
| `just eval` | 讓 AI 用固定的情境真的寫幾回合，再由程式與評審檢查：有沒有太早寫出結局、第三幕有沒有揭露真相、有沒有替玩家做決定、魯莽的選擇有沒有代價、文風符不符合題材。會呼叫真的 AI，免費方案全部跑完約六、七分鐘；結果存在 `eval_results/`，改提示詞前後可以比較 |

各測試檔驗證的內容見 [docs/files.md](docs/files.md#測試-tests)。

## 除錯

每回合 AI 提議了什麼變化、程式實際套用了什麼，都會記錄下來（每行一回合），遇到狀態變化不合理時可以從這裡查原因：

| 玩法 | 紀錄 |
|---|---|
| 終端機版 | `story_log.jsonl` |
| 網頁版各自玩 | `saves/名字.log.jsonl` |
| 網頁版線上多人 | `saves/party.log.jsonl` |

每一行的 `calls` 列出這段期間的每次 AI 呼叫：種類（`kind`：`genre` 挑題材、`arc` 規劃大綱、`turn` 劇情、`rewrite` 太早寫出結局時重寫、`death` 傷重倒下、`epilogue` 尾聲、`suggest` 幫我想、`compaction` 記憶壓縮）、花了幾秒（`seconds`），以及 Gemini 回報的 token 用量：送出（`prompt`）、其中命中快取（`cached`）、輸出（`output`）、思考（`thinking`）。覺得等很久時，可以從這裡看時間花在哪裡。

紀錄只會一直往後加，一局 30 回合約 50 KB。要清掉時執行 `just clean-logs`，只會刪除紀錄，不會動到存檔。
