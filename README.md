# Story

AI 文字冒險遊戲，可以在終端機或瀏覽器裡玩。劇情由 Gemini 即時生成，你的每個選擇都會影響故事的走向。

設計原則是 **AI 負責說故事，程式負責記憶與把關**：AI 每回合只「提議」劇情與狀態變化，由程式驗證後才寫進遊戲狀態，所以 AI 沒辦法一句話讓你死掉，也不會忘記你背包裡有什麼。

整個遊戲包成一個「最小核心」：跟呼叫 LLM 一樣，送文字進去、拿文字出來（附帶狀態等資料）。終端機、瀏覽器、純文字都只是外殼，要做 Discord 機器人之類的新外殼也只需要處理顯示和輸入。

## 特色

- **完整的故事結構**：開場前規劃隱藏的四幕大綱，連同一個玩家不知道的真相：前兩幕埋伏筆，第三幕揭露。程式追蹤進度、控制節奏，約 30 回合走到結局（節奏由程式把關，不會太早結束），最後附上尾聲與結局名稱
- **身體與精神狀況**：沒有生命值，改用「右臂撕裂傷（重）」「恐懼（中）」這類狀態。身體傷勢累積到致命才會死亡，精神狀態只影響表現
- **隱藏的遊戲內時間**：傷勢會隨時間痊癒，重傷則需要在劇情中接受治療
- **限時模式**：情勢緊迫時，要在倒數內做出決定
- **長期記憶**：每回合的劇情都保留原文，AI 看得到整段故事；故事長到超過上限時，最舊的部分才自動壓縮成摘要
- **隨機開頭**：開新故事時從題材包的開頭靈感裡隨機抽一個，按「換一個」重抽（不用等 AI），或按「幫我想」讓 AI 想一個全新的。再玩一次時延續上一局的前提
- **題材包**：武俠、克蘇魯、靈異、怪物與異形、賽博龐克等題材各有自己的寫作指引與轉折靈感，開局時依故事前提自動挑選，也可以自己指定。喜歡設計故事的人可以自己寫題材包加進來，不用改程式，見 [docs/genres.md](docs/genres.md)
- **多人模式**：2 到 4 位玩家各自扮演一位角色，每個人有自己的狀態、背包與選項，大家都行動後才推進一回合。可以在同一台電腦輪流玩，也可以透過網頁各自連線一起玩

## 需求

- [uv](https://docs.astral.sh/uv/)（會自動安裝 Python 3.14 與相依套件）
- Gemini API key，可以到 [Google AI Studio](https://aistudio.google.com/apikey) 免費申請

## 執行

裝了 [just](https://github.com/casey/just) 的話，常用指令都有捷徑：執行 `just` 會列出全部，例如 `just play`、`just web-party`、`just lan`、`just test`。下面是不用 just 的完整指令。

**終端機版**

```bash
uv run story
```

**多人模式**（大家輪流在同一台電腦上輸入行動）

```bash
uv run story --party
uv run story --plain --party   # 純文字版
```

**純文字版**（只用 input/print，可以看出核心的輸入輸出長什麼樣子）

```bash
uv run story --plain
```

**網頁版**

```bash
uv run story-web
```

接著在瀏覽器打開 <http://127.0.0.1:8080>。網頁版就是把終端機版原封不動地放進瀏覽器，畫面和操作完全相同，改功能時只要改一份。

網頁版是給多人各自遊玩的：

- 進入時先輸入名字，每個名字有自己的存檔（在 `saves/` 資料夾），同一個名字同時只能有一個人在線
- 每個玩家輸入自己的 Gemini API key，key 只留在這次連線裡，不會存到伺服器
- 同時在線最多 10 人（`web.py` 的 `MAX_SESSIONS`）

**線上多人**（大家各自用瀏覽器連進來，一起玩同一局）

```bash
export GEMINI_API_KEY=你的金鑰   # 線上多人用伺服器的 key，玩家不用輸入
uv run story-web --party
```

- 進入時輸入名字，名字就是你的角色。第一個進來的人是房主，2 到 4 人到齊後由房主選「開始遊戲」
- 房主負責選故事前提、要不要接續存檔、重新開始；房主送出前提後，大家會先看到前提，等 AI 寫好開場就一起進入故事
- 遊戲中每個人看到自己的選項，誰先行動都可以，有人行動時其他人會收到通知，大家都行動後才推進。限時模式的倒數由伺服器統一計時，等大家都看完劇情才開始
- 中途斷線可以用同一個名字回來；其他人都行動了而斷線的人還沒回來時，那個角色這回合算「暫時離開」
- 房主離線時，交給下一位在線的玩家當房主
- 故事結束後回到大廳，可以再玩一局。存檔在 `saves/party.json`，同一組玩家下次開始時可以接續

目前整台伺服器只有一個房間，大家都進同一局。

**用手機玩**：網頁版會自動切換成手機版面。畫面下方多一個輸入列，打字（包括中文選字）都在這裡輸入，按「送出」送進遊戲；什麼都不打直接送出等於按 Enter。選項可以直接點畫面，手指上下滑動可以捲動故事。電腦版不受影響；想在電腦上看手機版，可以在網址後面加上 `?mobile=1`。

預設只接受本機連線。要讓其他電腦連進來：

```bash
uv run story-web --host 0.0.0.0 --port 8080
```

> ⚠ 目前還沒有 HTTPS，玩家輸入的 API key 會以明文在網路上傳送，只建議在信任的網路裡開放。另外名字沒有密碼保護，知道名字的人可以讀取、接著玩那個存檔。

第一次執行時，遊戲會請你貼上 API key，並詢問要不要儲存（存在 `~/.config/story/api_key`）。也可以改用環境變數：

```bash
export GEMINI_API_KEY=你的金鑰
uv run story
```

## 操作

| 按鍵 | 功能 |
|---|---|
| ↑↓、數字、滑鼠 | 選擇選項 |
| 直接打字 | 自由行動，不照選項走 |
| Enter（文字顯示中） | 加速，再按一次全部顯示 |
| F2 | 選擇配色主題（上下移動就能預覽；終端機版會記住） |
| `/` 或 Ctrl+P | 開啟指令選單 |
| Ctrl+T | 看程式記住了什麼 |
| Ctrl+R | 重新開始 |
| F1 | 說明 |
| Ctrl+Q | 存檔並離開 |

在網頁版裡，瀏覽器會攔截 Ctrl+T、Ctrl+R、Ctrl+P、Ctrl+Q 這些按鍵（開新分頁、重新整理、列印、關閉瀏覽器）。請改用 `/` 開啟指令選單。

每回合都會自動存檔，下次執行時可以接續：終端機版存在目前資料夾的 `save.json`，多人模式存在 `party_save.json`（同一組玩家才會接續），網頁版存在 `saves/名字.json`，線上多人存在 `saves/party.json`。

## 調整

常用的設定都是程式檔開頭的常數：

- 故事長度、使用的模型、傷勢與痊癒規則：`src/story/core/engine.py`
- 預設配色主題、打字速度：`src/story/shells/textual/style.py`（網頁版會跟著一起變）。遊戲中按 F2 或輸入 `/theme` 可以換主題，傷勢與狀態的顏色會從主題的成功／警告／錯誤色算出來

每個檔案的詳細說明見 [docs/files.md](docs/files.md)。

## 測試

```bash
uv run pytest                  # 全部
uv run pytest -m "not slow"    # 略過會啟動真的伺服器的測試
```

測試不會連到 Gemini，也不會動到你的存檔或 API key。改完功能後跑一次，就能確認原本的功能沒有被弄壞。各測試檔驗證的內容見 [docs/files.md](docs/files.md#測試-tests)。

## 除錯

每回合 AI 提議了什麼變化、程式實際套用了什麼，都會記錄下來（每行一回合）：終端機版在 `story_log.jsonl`，網頁版在 `saves/名字.log.jsonl`，多人模式在 `party_log.jsonl`（線上多人在 `saves/party.log.jsonl`）。遇到狀態變化不合理時，可以從這裡查原因。

每一行的 `calls` 列出這段期間的每次 AI 呼叫：種類（題材、大綱、劇情、重寫、倒下、尾聲、幫我想、壓縮）、花了幾秒（`seconds`），以及 Gemini 回報的 token 用量：送出（`prompt`）、其中命中快取（`cached`）、輸出（`output`）、思考（`thinking`）。覺得等很久時，可以從這裡看時間花在哪裡。

紀錄只會一直往後加、不會自動清除（一局 30 回合約 50 KB）。要清掉時執行 `just clean-logs`，只會刪除紀錄，不會動到存檔。
