# Story

AI 文字冒險遊戲，可以在終端機或瀏覽器裡玩。劇情由 Gemini 即時生成，你的每個選擇都會影響故事的走向。

設計原則是 **AI 負責說故事，程式負責記憶與把關**：AI 每回合只「提議」劇情與狀態變化，由程式驗證後才寫進遊戲狀態，所以 AI 沒辦法一句話讓你死掉，也不會忘記你背包裡有什麼。

整個遊戲包成一個「最小核心」：跟呼叫 LLM 一樣，送文字進去、拿文字出來（附帶狀態等資料）。終端機、瀏覽器、純文字都只是外殼，要做 Discord 機器人之類的新外殼也只需要處理顯示和輸入。

## 特色

- **完整的故事結構**：開場前規劃隱藏的四幕大綱，程式追蹤進度、控制節奏，約 40 回合走到結局，最後附上尾聲與結局名稱
- **身體與精神狀況**：沒有生命值，改用「右臂撕裂傷（重）」「恐懼（中）」這類狀態。身體傷勢累積到致命才會死亡，精神狀態只影響表現
- **隱藏的遊戲內時間**：傷勢會隨時間痊癒，重傷則需要在劇情中接受治療
- **限時模式**：情勢緊迫時，要在倒數內做出決定
- **長期記憶**：近期劇情保留原文，較舊的自動壓縮成摘要，玩再久也記得之前發生的事
- **「幫我想」**：讓 AI 隨機想一個故事開頭

## 需求

- [uv](https://docs.astral.sh/uv/)（會自動安裝 Python 3.14 與相依套件）
- Gemini API key，可以到 [Google AI Studio](https://aistudio.google.com/apikey) 免費申請

## 執行

**終端機版**

```bash
uv run story
```

**純文字版**（只用 input/print，可以看出核心的輸入輸出長什麼樣子）

```bash
uv run story --plain
```

**網頁版**

```bash
uv run story-web
```

接著在瀏覽器打開 <http://127.0.0.1:8080>。網頁版就是把終端機版原封不動地放進瀏覽器，畫面和操作完全相同，改功能時只要改一份。

網頁版是給多人各自遊玩的：

- 進入時先輸入名字，每個名字有自己的存檔（在 `saves/` 資料夾），同一個名字同時只能有一個人在線
- 每個玩家輸入自己的 Gemini API key，key 只留在這次連線裡，不會存到伺服器
- 同時在線最多 10 人（`web.py` 的 `MAX_SESSIONS`）

預設只接受本機連線。要讓其他電腦連進來：

```bash
uv run story-web --host 0.0.0.0 --port 8080
```

> ⚠ 目前還沒有 HTTPS，玩家輸入的 API key 會以明文在網路上傳送，只建議在信任的網路裡開放。另外名字沒有密碼保護，知道名字的人可以讀取、接著玩那個存檔。

第一次執行時，遊戲會請你貼上 API key，並詢問要不要儲存（存在 `~/.config/story/api_key`）。也可以改用環境變數：

```bash
export GEMINI_API_KEY=你的金鑰
uv run story
```

## 操作

| 按鍵 | 功能 |
|---|---|
| ↑↓、數字、滑鼠 | 選擇選項 |
| 直接打字 | 自由行動，不照選項走 |
| Enter（文字顯示中） | 加速，再按一次全部顯示 |
| `/` 或 Ctrl+P | 開啟指令選單 |
| Ctrl+T | 看程式記住了什麼 |
| Ctrl+R | 重新開始 |
| F1 | 說明 |
| Ctrl+Q | 存檔並離開 |

在網頁版裡，瀏覽器會攔截 Ctrl+T、Ctrl+R、Ctrl+P、Ctrl+Q 這些按鍵（開新分頁、重新整理、列印、關閉瀏覽器）。請改用 `/` 開啟指令選單。

每回合都會自動存檔，下次執行時可以接續：終端機版存在目前資料夾的 `save.json`，網頁版存在 `saves/名字.json`。

## 調整

常用的設定都是程式檔開頭的常數：

- 故事長度、使用的模型、傷勢與痊癒規則：`src/story/core/engine.py`
- 配色主題、打字速度、狀態顏色：`src/story/shells/textual/style.py`（網頁版會跟著一起變）

每個檔案的詳細說明見 [docs/files.md](docs/files.md)。

## 測試

```bash
uv run pytest                  # 全部
uv run pytest -m "not slow"    # 略過會啟動真的伺服器的測試
```

測試不會連到 Gemini，也不會動到你的存檔或 API key。改完功能後跑一次，就能確認原本的功能沒有被弄壞。各測試檔驗證的內容見 [docs/files.md](docs/files.md#測試-tests)。

## 除錯

每回合 AI 提議了什麼變化、程式實際套用了什麼，都會記錄下來（每行一回合）：終端機版在 `story_log.jsonl`，網頁版在 `saves/名字.log.jsonl`。遇到狀態變化不合理時，可以從這裡查原因。
